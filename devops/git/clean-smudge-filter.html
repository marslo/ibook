Git Runbook

▸ Invisible local patches

Keep a permanent local edit in a repo you don't own — a vim plugin, a vendored lib, a shared config — while git status stays clean, so git pull and git merge --ff-only ( e.g. :PlugUpdate ) keep working. Built on git's clean / smudge filter.

01 How it works

Git never compares the file on disk directly: content passes through clean on the way in and smudge on the way out. The repo stores upstream as-is; the disk holds the patched copy.

worktreepatched: \w.@
clean →strip the patch
← smudgeapply the patch
index / objectsupstream: \w .@
FilterDirectionRuns onResult
cleanworktree → gitgit add, git commit -a, git stash, content compare in git status / git diffgit only ever sees upstream
smudgegit → worktreegit checkout, git merge, git pull, git reset --hard, git cloneevery file write lands patched
PieceLocationRole
attribute.git/info/attributes<path> filter=<name> — which file uses which filter
filter.git/config → [filter "<name>"]clean / smudge commands, stdin → stdout
Local only

Both pieces live under .git/: never committed, never pushed, untouched by fetch / merge.

02 Runbook

Three steps: bind the file to a filter name, define the filter, then patch the current file and refresh the index stat.

1 · attribute
# .git/info/ may not exist, depending on the init template
$ mkdir -p .git/info
$ echo '<path> filter=<name>' >> .git/info/attributes
$ git check-attr filter <path>      # <path>: filter: <name>
2 · filter: clean un-patches, smudge patches
$ git config filter.<name>.clean    '<cmd: patched -> upstream>'
$ git config filter.<name>.smudge   '<cmd: upstream -> patched>'
$ git config filter.<name>.required true   # fail loudly instead of passing through
3 · patch + refresh the index stat
# apply <cmd: upstream -> patched> in place to <path>, then:
$ git add <path>   # stages nothing; only the cached size / mtime update
Step 3 is not optional

Git flags a size mismatch as modified without running clean. Until git add refreshes the index stat, git status shows M.

03 Verify

The first two print nothing; the third bypasses the filter and shows the patch on disk.

git sees upstream, disk holds the patch
$ git status --short                     # empty
$ git diff --cached --name-only          # empty
$ git show HEAD:<path> | diff - <path>   # raw compare → shows the patch

04 Rollback

Remove both pieces, then restore the upstream file.

remove the filter
$ git config --remove-section filter.<name>
$ sed -i '/filter=<name>/d' .git/info/attributes   # or rm it if it holds only this rule
$ git checkout -- <path>                            # restore upstream content

05 Gotchas

The filter hides one exact text change from git; everything else behaves normally.

GotchaDetail
clean must invert smudgeclean( smudge( upstream ) ) == upstream; breaks if upstream already contains the patched text §06
hidden from git onlygrep, the editor, git hash-object --no-filters, sign-column plugins comparing raw buffer vs blob still see the patch
real edits stay visibleonly the filtered text is hidden; any other change still shows in git status / git diff
.git/info/ may be missinga custom init.templateDir skips it → mkdir -p .git/info
re-clone drops the setup.git/ is recreated; re-run the runbook, or automate it from a post-install hook §08
large filesclean reads the whole file, but only when size / mtime changed
any command workssed, perl, jq, a script — anything reading stdin and writing stdout

06 When upstream ships the fix

smudge stops matching and becomes a no-op — but clean still matches the fixed text and reverts it in git's view. The file on disk stays correct; git's picture does not.

StageResult ( measured in a sandbox repo )
merge brings the fixM <path> right away dirty
a git add ( e.g. a post-update hook )stages the reverted text into the index
next merge --ff-onlyPlease commit your changes ... Aborting
Guard

Before setting up, ask HEAD whether the unpatched text is still there. git grep exits 1 when it is gone — tear the filter down instead.

self-remove once upstream is fixed
$ if ! git grep -qF '<unpatched>' HEAD -- <path>; then   # exit 1: upstream fixed
    git config --remove-section filter.<name>
    sed -i '/filter=<name>/d' .git/info/attributes
    git checkout HEAD -- <path>
  fi

07 Example · local log_level

app.conf upstream has log_level = info; locally it should always be debug.

localdebug filter
$ mkdir -p .git/info && echo 'app.conf filter=localdebug' >> .git/info/attributes
$ git config filter.localdebug.clean  "sed -e 's/^log_level = debug\$/log_level = info/'"
$ git config filter.localdebug.smudge "sed -e 's/^log_level = info\$/log_level = debug/'"
$ git config filter.localdebug.required true

$ sed -i 's/^log_level = info$/log_level = debug/' app.conf
$ git status --short   # M app.conf   ← size changed, stat not refreshed
$ git add app.conf
$ git status --short   # ( empty )

08 Example · coc.nvim pathRe

build/index.js gets \w .@ → \w.@, dropping the space from the path-completion char class. Without the filter, vim-plug's git merge --ff-only origin/release aborts with Your local changes ... would be overwritten.

cocpatch filter
$ cd ~/.vim/plugged/coc.nvim
$ mkdir -p .git/info && echo 'build/index.js filter=cocpatch' >> .git/info/attributes
$ git config filter.cocpatch.clean  'perl -pe '\''s/\\w\.@/\\w .@/g'\'''
$ git config filter.cocpatch.smudge 'perl -pe '\''s/\\w \.@/\\w.@/g'\'''
$ perl -i -pe 's/\\w \.@/\\w.@/g' build/index.js && git add build/index.js
PieceWhere
setup + guards:PlugCocRePatch() in ~/.marslo/vimrc.d/functions, exposed as :PlugCocRePatch
re-install hookPlug 'neoclide/coc.nvim', { 'do': ':PlugCocRePatch' } in vimrc.d/extension
day-to-dayjust :PlugUpdate
