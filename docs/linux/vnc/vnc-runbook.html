01 Display map

One display number per user, each a separate X server on its own port with its own ~/.vnc/passwd. Users are isolated by construction — nobody can enter another display without that display's password.

DisplayPortUserServiceManaged by
:15901marslo ownertigervncserver@:1migrated off the custom unit (§06)
:25902ubuntu guesttigervncserver@:2official mechanism
:35903iliad guesttigervncserver@:3official mechanism
Why not just vncserver@2

The old hand-rolled unit hardcoded User=marslo, and its @N was the display number — so vncserver@2/@3 would have opened more desktops as marslo, not sessions for other users. Multi-user needs the official display→user map below.

02 Enable VNC for another account

TigerVNC's packaged multi-user mechanism: a display→user map in /etc/tigervnc/vncserver.users plus the tigervncserver@ unit, which launches each session as the mapped user through a real PAM login.

map displays to users
# /etc/tigervnc/vncserver.users — one line per display
$ sudo tee /etc/tigervnc/vncserver.users >/dev/null <<'EOF'
:1=marslo
:2=ubuntu
:3=iliad
EOF
per-user password + start
# each user gets their OWN password (run as that user)
$ sudo -iu ubuntu vncpasswd
$ sudo -iu iliad  vncpasswd

# start now + on boot (instance name includes the colon)
$ sudo systemctl enable --now tigervncserver@:2.service
$ sudo systemctl enable --now tigervncserver@:3.service
Note — each guest needs their own ~/.vnc

A password (vncpasswd) plus an xstartup for XFCE, or they land in the system default session. Options come from their own ~/.vnc/tigervnc.conf (§03).

03 Per-user config — ~/.vnc/tigervnc.conf

The tigervncserver@ unit reads options from a config file, not the command line. It is Perl syntax and must end in 1;. Geometry, depth, and network exposure live here.

~/.vnc/tigervnc.conf
# Perl syntax — sourced per user
$geometry  = "1920x1080";
$depth     = "24";
$localhost = "no";   # listen on all interfaces; "yes" = localhost-only
1;
Warning — the localhost default flips to “yes”

With the default VncAuth security type, TigerVNC defaults to $localhost="yes" — localhost-only, unlike the old custom unit's -localhost no. For direct network access set $localhost="no" explicitly. Otherwise guests reach it only over an SSH tunnel — the safer default (see §08).

04 The xstartup reference

Kept in each user's ~/.vnc/xstartup. This is the marslo copy.

~/.vnc/xstartup
#!/bin/sh
unset SESSION_MANAGER
unset DBUS_SESSION_BUS_ADDRESS

# runtime dir; avoids apps falling back to /tmp (PAM login also provides it now)
test -d "/run/user/$(id -u)" && export XDG_RUNTIME_DIR="/run/user/$(id -u)"

# desktop identity; ":GNOME" makes the portal pick the GTK FileChooser backend (UseIn=gnome)
export XDG_CURRENT_DESKTOP=XFCE:GNOME

# clipboard bridge between vnc viewer and X
vncconfig -nowin &
autocutsel -fork
autocutsel -selection PRIMARY -fork

# disable X screensaver / blanking
xset s off -dpms 2>/dev/null

# DPI has no tigervnc.conf knob — set it here
xrandr --dpi 120 2>/dev/null

exec dbus-run-session -- startxfce4
  • dbus-run-session — neither startxfce4 nor the Xfce xinitrc starts a session bus, and (as a system-service child) XDG_RUNTIME_DIR isn't inherited, so the systemd user bus isn't the default either. This guarantees a private bus and tears it down cleanly on logout.
  • XDG_CURRENT_DESKTOP=XFCE:GNOME — the :GNOME is what lets the portal serve the file-chooser (see §05). Drop it to XFCE only if you deliberately disable the portal.

05 Browser file uploads (Chrome & Firefox)

Chrome ≥123 and Firefox hand the file-picker to xdg-desktop-portal when it's reachable. How well that dialog behaves depends almost entirely on the portal version — which is exactly why the 24.04 upgrade mattered.

Resolved on 24.04 — keep the portal ON

With xdg-desktop-portal 1.18 the portal dialog now double-clicks to upload AND remembers the last folder, in both Chrome and Firefox. Nothing to configure beyond leaving the portal enabled. On 22.04's 1.14 you couldn't get both at once — the upgrade dissolved the trade-off.

Portal versionDouble-click uploadsOpens at
1.18 — Ubuntu 24.04 nowyeslast-used folder
1.14 — Ubuntu 22.04closed dialog without uploading$HOME (never last dir)

How “portal ON” is wired

  • Packages xdg-desktop-portal + xdg-desktop-portal-gtk installed, and no shadow file overriding the D-Bus service.
  • ~/.vnc/xstartup sets XDG_CURRENT_DESKTOP=XFCE:GNOME — the :GNOME is required so the portal picks the GTK FileChooser backend (its gtk.portal declares UseIn=gnome).

Fallback — turn the portal OFF (rarely needed on 24.04)

Shadow the portal's D-Bus activation for your user and set XDG_CURRENT_DESKTOP=XFCE; Chrome then falls back to its own GTK dialog (remembers the dir, but on 22.04 double-click closed it without uploading). Kept for reference.

disable the portal for your user
$ mkdir -p ~/.local/share/dbus-1/services
$ tee ~/.local/share/dbus-1/services/org.freedesktop.portal.Desktop.service <<'EOF'
[D-BUS Service]
Name=org.freedesktop.portal.Desktop
Exec=/bin/false
EOF
# restart the session; delete the file to re-enable
Warning — systemctl --user mask does NOT work here

The session runs on a dbus-run-session bus whose session.conf has no systemd activation, so the portal is activated directly by dbus-daemon — masking the systemd unit is bypassed. Shadowing the D-Bus service file is the reliable, bus-agnostic lever.

Firefox — install the deb, not the snap

The snap build fails in this VNC session with … is not a snap cgroup for tag snap.firefox.firefox (snap-confine can't track the session's cgroup). Use Mozilla's apt repo, like the deb Chrome, and pin it so upgrades never switch it back to the snap:

firefox: mozilla deb + pin out the snap
$ sudo install -d -m 0755 /etc/apt/keyrings
$ wget -q https://packages.mozilla.org/apt/repo-signing-key.gpg -O- \
    | sudo tee /etc/apt/keyrings/packages.mozilla.org.asc > /dev/null
$ echo "deb [signed-by=/etc/apt/keyrings/packages.mozilla.org.asc] https://packages.mozilla.org/apt mozilla main" \
    | sudo tee /etc/apt/sources.list.d/mozilla.list > /dev/null

# pin: Mozilla's firefox wins (1000), Ubuntu's snap-stub blocked (-1)
$ sudo tee /etc/apt/preferences.d/mozilla-firefox >/dev/null <<'EOF'
Package: firefox*
Pin: origin packages.mozilla.org
Pin-Priority: 1000

Package: firefox*
Pin: release o=Ubuntu
Pin-Priority: -1
EOF
$ sudo apt update; sudo snap remove firefox 2>/dev/null; sudo apt purge -y firefox; sudo apt install -y firefox

06 Retire the custom unit

done marslo's :1 was moved off the hand-rolled /etc/systemd/system/vncserver@.service onto the official mechanism. Bonus — tigervncsession opens a real PAM login, so XDG_RUNTIME_DIR is populated for free.

  1. CLI options moved to ~/.vnc/tigervnc.conf (§03) — geometry, depth, localhost.
  2. -dpi 120 moved into ~/.vnc/xstartup (§04) — no config knob for it.
  3. ~/.vnc/xstartup carries over automatically.
switch marslo onto the official unit
# :1=marslo added to /etc/tigervnc/vncserver.users, then:
$ sudo systemctl disable --now vncserver@1.service
$ sudo systemctl enable  --now tigervncserver@:1.service
Note — custom unit disabled, kept as a fallback

/etc/systemd/system/vncserver@.service is disabled but not deleted. It survived the 24.04 upgrade and tigervncserver@:1 auto-starts on boot. Rollback: sudo systemctl disable --now tigervncserver@:1 && sudo systemctl enable --now vncserver@1.

07 The 22.04 → 24.04 upgrade

Done in-place over SSH with do-release-upgrade. The gotchas below are the ones that actually bit.

the upgrade itself
# ALWAYS in tmux/screen — a dropped SSH mid-upgrade can wreck the box
$ tmux new -s upgrade
$ sudo apt update && sudo apt full-upgrade -y && sudo apt --purge autoremove -y
$ sudo do-release-upgrade   # opens a backup sshd on :1022; keep old configs (sshd_config!)

Disk was 88% full — grow the LV online

/ is an LVM ext4 volume with free space in the VG. Extend it live — no unmount, no reboot, no data loss (growing is safe; only shrinking is risky):

lvextend + online resize2fs in one step
$ sudo lvextend -L 200G -r /dev/ubuntu-vg/ubuntu-lv   # -r also grows the ext4 fs
Note — when the VG itself is full (VFree = 0)

Feed capacity from the bottom first: a new disk → pvcreate + vgextend; or an enlarged disk → growpart + pvresize. Then lvextend -r. Diagnose with vgs (VFree) and pvs (PFree). Canonical LV path: lvs -o lv_path.

After the upgrade: third-party apt repos

do-release-upgrade disables third-party sources (renames them *.list.distUpgrade). Re-enable the ones you use for noble. Two bit us:

Marvell Artifactory mirror — 24.04's apt rejects it as unsigned

The mirror serves an unsigned Release (Origin: Artifactory; no InRelease/Release.gpg, no key endpoint), so Signed-By is impossible. Add Trusted: yes to its deb822 stanza in /etc/apt/sources.list.d/third-party.sources. The leftover N: Missing Signed-By lines are harmless notices (not errors); only Artifactory-side GPG signing removes them — an IT request.

Firefox — the upgrade tries to revert it to the snap

With the Mozilla repo disabled during the upgrade, apt reinstalls Ubuntu's snap-transition firefox (the “Configuring firefox → snap” dialog). Press Ok, let it finish, then re-enable the Mozilla repo and apply the pin from §05 to keep the deb permanently.

08 Hardening

Security — VNC auth is weak

~/.vnc/passwd is reversibly obfuscated (fixed DES key), not hashed, and only the first 8 characters matter. Treat a VNC password as low-trust: never reuse it elsewhere.

For a shared server, don't leave the ports open. Prefer localhost-only + SSH tunnel:

connect over ssh — from the client
# set $localhost="yes" in tigervnc.conf, then tunnel the port
$ ssh -L 5902:localhost:5902 ubuntu@sj4dl360n4u20
# then point the VNC viewer at  localhost:5902
  • Only SSH-authenticated users can reach the VNC port — the biggest single win.
  • If you must expose ports ($localhost="no"), firewall 5901-5903 to trusted IPs and give each user a distinct password.

09 Forgot a VNC password

Just reset it — no old password needed

reset
$ vncpasswd                                       # rewrites ~/.vnc/passwd
$ sudo systemctl restart tigervncserver@:1.service

Recover the old plaintext (it's decryptable)

Because the file is fixed-key DES, the original (first 8 chars) can be decrypted. The VNC key {23,82,107,6,35,78,88,7} is fed with each byte bit-reversed → E84AD660C4721AE0, which standard OpenSSL DES accepts.

decrypt — prints to your own terminal only
$ openssl enc -des-ecb -d -nopad -K E84AD660C4721AE0 \
    -provider legacy -provider default \
    -in ~/.vnc/passwd 2>/dev/null | head -c 8 | tr -d '\0'; echo
Note

OpenSSL 3 (Ubuntu 22.04+) needs -provider legacy -provider default; drop them on OpenSSL 1.1. A 16-byte file also holds a view-only password in bytes 9–16 (tail -c +9 | head -c 8).

10 Troubleshooting

“A Xtigervnc server is already running” (legacy custom unit)

The old custom unit had a latent bug — systemd runs no shell, so the redirect in ExecStartPre=-/usr/bin/vncserver -kill :%i > /dev/null 2>&1 became literal arguments and the pre-kill failed every time. Fix: drop the redirect. If a restart still refuses:

clear a stuck display
$ vncserver -kill :1
# if it complains about stale locks:
$ rm -f /tmp/.X1-lock /tmp/.X11-unix/X1 ~/.vnc/*:1.pid

Bus / env values differ between shells — expected

Values depend on where you run the command, not on any misconfig:

ContextDBUS_SESSION_BUS_ADDRESSXDG_RUNTIME_DIRDISPLAY
SSH login shellunix:path=/run/user/1100/bus/run/user/1100(empty)
Terminal inside VNCunix:abstract=/tmp/dbus-…/run/user/1100:1.0

The VNC session runs on its own dbus-run-session bus (a /tmp abstract socket), while an SSH login uses the systemd user bus from pam_systemd. To poke the VNC session's bus from SSH, read a session process's env: tr '\0' '\n' < /proc/$(pgrep -u marslo -x xfce4-session)/environ.
